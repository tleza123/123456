# คำสั่งสำหรับ Gemini

สร้างเว็บ DE TEAM ตาม BLUEPRINT.md ที่แนบ โดยอ่านเอกสารทั้งหมดก่อนเริ่ม ใช้ Apps Script HTML Service และ Google Sheets เท่านั้น รวม Advanced Sheets Service ได้ ไม่เพิ่ม Firebase, Drive เก็บภาพ, server ภายนอก, framework หนัก หรือบริการเสียเงิน

ผู้ใช้เป็นเจ้าของ/ผู้ดูแลคนเดียว ใช้มือถือและมีทักษะเทคโนโลยีน้อย จุดสำคัญที่สุดคืออ่านง่าย กดง่าย ลื่น ไม่ต้องเปิดชีตทำงานประจำวัน มีแค่ 3 แท็บ เช็คชื่อ / รายงาน / ตั้งค่า

กติกาที่อนุมัติ: เต็มวัน 1 เท่า ครึ่งวัน 0.5 เท่า ไม่มา 0 บาท ยังไม่เช็คไม่ใช่ไม่มา เงินพิเศษเป็นยอดเต็มรายเดือนพร้อมชื่อรายการที่พิมพ์เองได้หลายรายการ

ใช้พื้นทึบ น้ำเงิน #003566 เหลือง #FFC300 ขาวและเทาอ่อน ฟอนต์ Sarabun แบบมีหัว 400/700 เนื้อหาประมาณ 18px บนมือถือ ปุ่มหลักอย่างน้อย 52px ไม่มีอิโมจิ blur glass glow letter-spacing ติดลบ หรือภาพครอป

ใช้ preview.html เป็นตัวอย่างลำดับและการกด ไม่ถือว่าเป็น production และอย่าคัดลอกข้อมูลสมมติลงชีตจริง อ่าน Payroll.gs, AttendanceService.gs และ ClientBridge.html เป็นตัวอย่างแกนระบบ ส่วนที่ยังขาดตาม API contract ต้องเขียนให้ครบ ไม่แสร้งว่าโค้ดอ้างอิงคือระบบสมบูรณ์

ต้องป้องกันข้อมูลเสียด้วย employeeId, revision, requestId, persistent receipt, ScriptLock และ atomic batch สำหรับ data + audit + receipt ตรวจ auth ฝั่ง server ทุก endpoint ปิดการเข้าถึงสาธารณะ Deploy ผู้ดูแลคนเดียว ไม่สร้าง password ไว้ใน HTML

ต้องเก็บประวัติอัตราค่าแรงตามวันมีผล เงินพิเศษรายเดือนแยกจาก template วันทำงานแยกจากวันหยุด ปิดเดือนด้วย snapshots และคงยอดเก่าเมื่อเปลี่ยนการตั้งค่า พนักงานออกใช้ endDate ไม่ลบประวัติ

ก่อนลงมือแสดงสรุปไฟล์/ลำดับพัฒนาอย่างสั้น แล้วดำเนินงานให้ครบ ใช้ข้อเสนอเริ่มต้นในพิมพ์เขียวสำหรับประเด็นที่ยังไม่ยืนยันและแสดงให้เจ้าของปรับได้ ไม่เพิ่มข้อกำหนดเงินเดือนเองอย่างเงียบ ๆ

ส่งมอบ:

1. ไฟล์ .gs/.html/manifest ครบทุกไฟล์ ไม่มี TODO ใน feature ที่กดได้
2. setupSystem_ ที่ idempotent และไม่ล้างข้อมูลเดิม
3. Fonts.html พร้อม WOFF2 จริงและใบอนุญาต หรือระบุว่ายังขาดไฟล์ ห้ามปลอม base64
4. คู่มือไทยติดตั้งทีละขั้น เปิด Sheets API ตั้ง Script Properties ตั้ง timezone และ deploy Only myself
5. tests สูตรเงิน, idempotency, conflict, month lock, auth, validation, snapshot และ responsive
6. รายงานผลทดสอบจริง แยก local/mock กับ Google deployment พร้อมข้อจำกัดที่ยังไม่ทดสอบ

อย่าแก้ระบบสั่งเสื้อเดิมหรือใช้ Spreadsheet เดิมร่วมกับงานนี้ อย่าใส่ credential หรือข้อมูลพนักงานจริงใน repository อย่าอ้างผล 0ms, 120FPS ทุกเครื่อง หรือไม่มีบั๊ก 100% โดยไม่มีหลักฐาน
